# 구현 설계

기존 React/Vite와 FastAPI 구조를 유지한다. backend/app/team에 관광 API, 수집 어댑터, 별도 통계 수집 명령을 둔다. 기본 Record 모델·DB 연결·잠금 파일은 유지한다.

TourAPI 목록은 고정된 시연 중심점으로 조회한다. 서버에서 지원 경계·좌표·유형·방문 기록을 필터링하고 Haversine 직선거리로 정렬한다. 동일 점수는 거리와 장소 ID로 결정한다. 운영시간은 연중무휴와 명확한 당일 구간만 해석한다.

목록은 1시간 캐시하며 조회 실패 시 최대 24시간 이내 캐시를 시점과 함께 제공한다. 상세정보는 요청 시 조회한다. 원천 오류 응답에 URL이나 인증키를 노출하지 않는다.

중심·연관 통계는 별도 명령으로 월을 명시해 수집한다. 이름 정규화와 250m 이내 좌표, 단일 후보가 일치할 때만 연결한다. 현재 확인된 매칭은 0건이므로 거리 이외 요인은 랭킹에 반영하지 않는다.

방문·제외 ID 및 공개 장소 정보는 탭 세션에 저장하고 실제 사용자 위치는 메모리에서만 사용한다. 익명 이벤트는 별도 SQLite에 저장하며 쓰기 시 30일 초과 기록을 정리한다. 지도는 OpenStreetMap, 길찾기는 외부 Kakao 지도 링크를 사용한다.
